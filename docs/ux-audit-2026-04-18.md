## Dimension Detail

### D1 — Visual Design & Brand Consistency (8/10)

**Strengths:**
- Fraunces variable font with automated `opsz` axis (`fontVariationSettings: '"opsz" 9'`) — deliberate, rare choice
- Warm off-white `paper` (#FAFAF7) + single `brand-700` accent blue — distinctive and restrained
- Full semantic token system: `ink-900/700/500`, `brand-700/300`, `surface-1/2/3`, `paper`
- Fluid `clamp()` type scale across 8 named tokens (`typography-display-xl` → `typography-caption`)
- Strong visual rhythm: `border-surface-2` section dividers, consistent `py-24 md:py-32` cadence
- Asymmetric 12-column grid (4+8 splits) creates editorial tension

**Gaps:**
- No illustration or imagery strategy — text-only is a deliberate choice but can feel cold on conversion pages
- `brand-700` is the only accent; secondary accent would add depth without breaking restraint

---

### D2 — Interaction & Micro-interactions (7/10)

**Strengths:**
- Hover states: `hover:bg-surface-2/60` on cards, `hover:decoration-brand-500` on underlined links
- Arrow translation: `group-hover:translate-x-1` on all CTA links — consistent signature
- FAQ `<details>/<summary>` with `group-open:rotate-45` for `+` icon — semantic and elegant
- `transition-colors`, `transition-transform` applied correctly throughout

**Gaps:**
- **FOIC (Flash of Industrial Content):** `usePersona` reads cookie in `useEffect` → SSR renders `industrial`, hydration triggers re-render to `commerce`. Visible text flash on repeat visits with commerce persona set.
- No scroll-driven animations or `animation-timeline: scroll()`
- No `@starting-style` entry animations for sections
- No loading skeleton patterns
- View Transitions API not wired for page navigations

---

### D3 — Accessibility / WCAG 2.2 (7/10)

**Strengths:**
- Color contrast: `ink-900` on `paper` and `ink-700` on `surface-1` verified WCAG AA/AAA
- `aria-hidden="true"` on all decorative arrow characters
- `aria-labelledby` pairing on all `<section>` elements
- `prefers-reduced-motion` respected on animations
- Semantic HTML: `<dl>/<dt>/<dd>` for metrics, `<ol>` for methodology, `<details>/<summary>` for FAQ
- Heading hierarchy correct: `h1` (PageHeader title) → `h2` (sections) → `h3` (subsections)
- Breadcrumbs present on all detail pages

**Gaps:**
- **No skip navigation link** — keyboard/screen reader users must tab through entire nav on every page. Critical blocker for WCAG 2.4.1.
- Focus indicators: default browser outlines — not customized to match brand
- No `role="alert"` or live region patterns for PersonaText switches (assistive tech won't announce content change)
- WCAG 2.2 target size (24×24px minimum) not verified on smaller interactive elements
- Mobile navigation state unknown (see D5)

---

### D4 — Performance & Core Web Vitals (7.5/10)

**Strengths:**
- Full SSG via `generateStaticParams` on all parameterized routes — TTFB near-zero
- RSC by default, client islands (`PersonaText`, `PersonaListItems`, `PopupCTAButton`) minimal and focused
- No images on audited pages → no CLS risk from image loading, no LCP image optimization needed
- Variable font (single file covers all weights) vs. multiple static font files
- GPU-accelerated CSS transitions only (`transform`, `opacity`) — no layout-thrashing animations
- `font-display: swap` assumed (Next.js default with `next/font`)

**Gaps:**
- Speculation Rules API not wired — `/paketler` → `/paketler/[slug]` is a full navigation even though all targets are statically pre-rendered
- No explicit `preconnect` / `dns-prefetch` resource hints visible in layout
- No `content-visibility: auto` on off-screen sections
- Third-party script inventory unknown (analytics, chat widgets)

---

### D5 — Mobile-First & Responsive (5.5/10)

**Strengths:**
- Responsive grid system with `md:` breakpoints throughout — layout reflows correctly
- CTA buttons sized at `h-12` (48px) — meets Material Design 48dp minimum
- `max-w-prose-editorial` prevents line lengths from becoming unreadable

**Gaps:**
- **Mobile navigation not implemented** — no hamburger menu, no drawer, no mobile nav component found in codebase. This is the most impactful gap.
- `vh` units still in use — should be `dvh`/`svh` for mobile browsers with dynamic toolbars (Safari iOS, Chrome Android)
- No PWA `manifest.json` — no install prompt, no standalone mode, no themed status bar
- No container queries (`@container`) — breakpoint-based only
- No `env(safe-area-inset-*)` for notch / Dynamic Island support
- No `@media (hover: none)` differentiation for touch vs. pointer interfaces
- No offline/Service Worker strategy
- PersonaText switching behavior on mobile not tested; FOIC may be more visible on slower mobile CPUs

---

### D6 — Information Architecture & Navigation (7.5/10)

**Strengths:**
- Breadcrumbs on all detail pages (`hizmetler/[slug]`, `paketler/[slug]`) — correct hierarchy
- URL structure semantic and human-readable: `/[locale]/hizmetler/[slug]`, `/[locale]/paketler/[slug]`
- Pillar → Service → Package hierarchy clearly expressed in both IA and URLs
- Cross-links: pillar detail page shows related packages; package detail shows related case study
- TR + EN path-based i18n — correct implementation (not query params or cookie-based)
- Empty states: `notFound()` called correctly when slug doesn't match

**Gaps:**
- No search functionality
- No command palette (⌘K) for power users
- `/vakalar` (case studies) cross-links exist but case study detail pages not in audit scope
- No "related services" links from package detail back to full pillar

### D7 — AI-Readiness & Modern Web Patterns (5/10)

**Strengths:**
- `llms.txt` exists at `/src/app/llms.txt` — ahead of most peers
- TR+EN structured content in consistent JSON schema (`messages/tr.json`, `messages/en.json`)
- Persona system is itself a form of sophisticated content personalization

**Gaps:**
- No `application/ld+json` schema.org structured data anywhere — services, packages, and the organization are invisible to AI crawlers as structured entities
- No rich snippets for Google (Service, Offer, Organization, BreadcrumbList)
- `llms.txt` content likely minimal — should include service descriptions, pricing ranges, contact info
- No AI assistant / chat integration on site (planned via `/[locale]#chat` anchor but not visible in audited pages)
- No streaming UI patterns

### D8 — Ethical Design & Trust (8/10)

**Strengths:**
- Prices (TRY + EUR) fully visible on `/paketler` listing and detail pages — no "contact for pricing" dark pattern
- No forced registration before browsing
- Persona system opt-in via popup (not forced or manipulative)
- Minimal cookie footprint (popup state only, no tracking wall)
- TR + EN localization — inclusive of Turkish-speaking audience without degrading to machine translation
- `rel="noopener"` assumed on external links (Next.js Link default)

**Gaps:**
- Cookie consent UX not audited (depends on `/app` shell)
- Privacy policy / KVKK linkage not verified on audited pages
- No carbon/sustainability metrics

---

### D9 — Design Originality & Differentiation (8/10)

**Template Dependency Audit:**
- Tailwind present but surface tokens (`paper`, `ink-*`, `brand-*`, `surface-*`) depart significantly from defaults
- No shadcn/ui component DNA detected
- No Lucide/Heroicons icon monoculture — arrows are plain text characters, decorative only
- No hero→features→testimonials→CTA formula — broken by editorial 12-col asymmetry and metrics strips

**Visual Signature:**
- Fraunces variable with `opsz` automation is unmistakable — cannot be confused with Inter/Geist defaults
- Warm paper palette with single blue accent is specific and recognizable
- Section rhythm via `border-surface-2` dividers creates a consistent cadence without box shadows or cards everywhere
- `typography-display-xl` through `typography-caption` — 8-token scale is distinctive

**Differentiator:**
- ADR-014 dual-persona system (industrial vs. commerce) is genuinely novel — no template or AI tool produces this
- The `_personas` subtree architecture in messages JSON is a competitive moat

**Verdict:** Could not be trivially replicated by AI prompting alone. Design fingerprint is present and deliberate.

## Critical Issues (Must Fix)

### C1 — No Skip Navigation Link
**Dimension:** Accessibility (D3)
**WCAG:** 2.4.1 Bypass Blocks (Level A) — **mandatory**
**Impact:** Keyboard and screen reader users must tab through entire navigation on every page load.
**Fix:**
```html
<!-- First child of <body> in root layout -->
<a
  href="#main-content"
  className="sr-only focus:not-sr-only focus:fixed focus:top-4 focus:left-4 focus:z-50 focus:px-4 focus:py-2 focus:bg-ink-900 focus:text-paper focus:rounded-lg"
>
  Skip to content
</a>
```
Add `id="main-content"` to `<main>` element.
**Effort:** XS — < 30 minutes

---

### C2 — Mobile Navigation Not Implemented
**Dimension:** Mobile-First (D5), IA (D6)
**Impact:** Primary navigation inaccessible on mobile viewports. Affects 100% of mobile users.
**Fix:** Implement `MobileNav` drawer component using Popover API or `useState` toggle.
Requirements: `aria-expanded` on trigger, focus trap inside drawer, Escape key dismissal, `aria-controls` linking trigger to panel.
**Effort:** M — 1–2 days

---

### C3 — FOIC on Persona Switch
**Dimension:** Interaction (D2), Accessibility (D3)
**Impact:** On repeat visits with `commerce` persona set, `industrial` text renders server-side then switches post-hydration. Visible flash, confusing for screen readers.
**Fix Option A (CSS):** Wrap `PersonaText` output in `<span className="transition-opacity duration-150">`. On mount, set `opacity-0` → `opacity-100` after hydration.
**Fix Option B (Synchronous):** In `usePersona`, use `useLayoutEffect` + synchronous `document.cookie` read to avoid the SSR mismatch entirely. Note: requires careful handling of SSR/CSR boundary.
**Gate behind:** `@media (prefers-reduced-motion: no-preference)`
**Effort:** S — 2–4 hours

## Significant Improvements (Should Fix)

### I1 — No Schema.org Structured Data
**Dimension:** AI-Readiness (D7)
**Impact:** Service pages, package pages, and organization data invisible to AI search crawlers (Perplexity, SearchGPT, Gemini, Google AI Overviews) as structured entities. No rich snippets.
**Fix:** Add `application/ld+json` blocks:
- Root layout: `Organization` schema (name, url, contactPoint, logo)
- `/hizmetler/[slug]`: `Service` schema (name, description, provider, areaServed)
- `/paketler/[slug]`: `Offer` schema (name, price, priceCurrency, description)
- All pages: `BreadcrumbList` schema
**Effort:** S–M — 4–8 hours

### I2 — No PWA Manifest
**Dimension:** Mobile (D5)
**Impact:** No install prompt on mobile, no standalone display mode, no themed browser chrome.
**Fix:** Create `/public/manifest.json`:
```json
{
  "name": "INDOLES",
  "short_name": "INDOLES",
  "theme_color": "#FAFAF7",
  "background_color": "#FAFAF7",
  "display": "standalone",
  "start_url": "/tr",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```
Add `<link rel="manifest" href="/manifest.json">` to root layout metadata.
**Effort:** XS — < 1 hour (plus icon generation)

### I3 — `vh` → `dvh` Viewport Units
**Dimension:** Mobile (D5)
**Impact:** On mobile browsers with dynamic toolbar (Safari iOS, Chrome Android), `100vh` extends behind toolbar on initial load causing layout shift.
**Fix:** Replace `min-h-screen` (which resolves to `min-height: 100vh`) with `min-h-[100dvh]` where full-viewport height is needed. `dvh` is Baseline 2023.
**Effort:** XS — < 1 hour

### I4 — Missing `autocomplete` on Brief Form
**Dimension:** Mobile (D5)
**Impact:** Mobile users get no autofill on `/app/brief/yeni`, the primary conversion path.
**Fix:** Add `autocomplete="name"`, `autocomplete="email"`, `autocomplete="organization"` to form inputs. Add `inputmode="email"` to email fields.
**Effort:** XS — < 30 minutes

### I5 — Speculation Rules API
**Dimension:** Performance (D4)
**Impact:** `/paketler` → `/paketler/[slug]` navigations are full page loads despite all targets being statically pre-rendered.
**Fix:** Add `<script type="speculationrules">` in layout for prefetch-on-hover on package links.
**Effort:** XS–S — 1–2 hours

### I6 — Custom Focus Indicators
**Dimension:** Accessibility (D3)
**Impact:** Default browser focus outlines (blue ring or none) don't match brand. Low contrast in some browsers.
**Fix:** Add `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-brand-700` to interactive element base styles in Tailwind config or global CSS.
**Effort:** S — 2–4 hours (systematic, not per-element)
